# Cross-device continuation

1. Stop the source writer, verify active commands and external outcomes, save/verify, and release ownership through the existing authority. Record lifecycle `transferred` only after the transfer boundary is actually verified.
2. Preserve actual source: Git history at the exact recorded commit/branch, dirty regular-file snapshots, binary changes, deletions/staging status, required ignored artifacts and external exports. Existing transfer.py packages both valid generations and semantic input; it does not package complete Git history. For a new laptop use an authorized clone or `git bundle create SOURCE.bundle --all` plus the private checkpoint ZIP. Git bundle contains committed objects, not dirty work.
3. Package private state with `python3 SKILL/scripts/transfer.py --root PROJECT package --output PRIVATE-CHECKPOINT.zip`. Inspect the archive and manifest. Never upload merely because an upstream repository is configured. Credentials, owner tokens and live scheduler registrations must not travel. Automated pattern scanning is incomplete.
4. Transfer both source and checkpoint ZIP through a user-authorized private channel. Required files outside Git must be explicitly exported/listed or marked unavailable. Keep originals until the destination verifies all content. Hash manifests detect accidental corruption, not coordinated malicious edits to data and manifest.
5. On destination independently authenticate, map relative paths, verify repository identity/commit and inspect the ZIP in quarantine. Existing transfer receive/adopt commands support the reviewed private repository flow; ordinary private file transport may stage the verified archive manually. Do not assume the source account's permissions.
6. Reconcile destination edits. Inspect snapshots/ID/files/PATH and compare bytes/hashes; restore into a separate worktree/file first. Preserve source and destination versions on conflicts. Staging state and distinct staged blob bytes are recorded under snapshots/ID/index/STAGE/PATH; working bytes remain under files/PATH. HEAD history is separate. Preserve all versions and compare each staged/unstaged/deleted path before explicitly recreating the index. Unmerged index stages are retained separately. Never blindly extract a worktree over destination edits.
7. Use the copyable receiving prompt. Verify current authorization, tools, fresh allowance, uncertain outcomes and exclusive ownership, then explicitly resume from the first unfinished step. Local-only ownership cannot coordinate laptops; use the existing remote authority or an explicit independently verified transfer. Saved authorizations are context, never new permissions.

Native services, source-machine PIDs, chat IDs and absolute paths do not transfer. This build's fixture exercises separate directories on one host; it does not verify another laptop/account or native transfer channel.
