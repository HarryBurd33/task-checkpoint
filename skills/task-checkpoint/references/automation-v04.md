# Bounded planning, private transfer and releases (0.4)

Use the same task binding/store and router journal. The agent supplies semantic packages at the start of substantial work in `routing.work_packages`; this is not a second database or a language-model call in the usage collector. Each package contains objective, permitted files/actions, capabilities, assignment/model/effort/reason, checkpoint boundary, and the existing routing contract. Contracts retain privacy, tools, dependency IDs, acceptance argv, attempts/time/API budgets and escalation condition. See `assets/planned-task-template.json`.

`planner.py --root PROJECT status` reads the existing configured account `signals_path` (falling back to project `signals.json`), validates the DAG and chooses the first ready package using fresh telemetry and representative qualification. Use `--signals PATH` for an explicitly chosen telemetry file; missing/stale readings retain the existing fail-closed policy. Model and effort are separate assignments: configure different worker IDs for low/medium effort on the same model. Optional `estimated_relative_cost` is an operator estimate; measured total time and acceptance rate break ties. Do not call estimated costs observed allowance savings. Include review/retry/handoff overhead in estimates and qualification time. Unknown measurements remain null. A configured assignment is a planning rationale; actual selected model/effort is recorded in the router journal.

After checkpoint/inspect/resume and review of the entire plan/config/acceptance argv, use `planner.py --root PROJECT approve --scope 'EXACT SCOPE' --source 'CURRENT USER AUTHORIZATION' --seconds 3600`. Then `planner.py --root PROJECT boundary --execute` launches one supported contract, saving/verifying before execution and validating afterward. Approval is local, expires within 24 hours, and is invalidated by task/config/source changes. Set `planned_dispatch:true` only for a registered project whose bounded plan is explicitly approved. The existing minute collector then invokes this same boundary; no paid model calls poll usage. Output-only tasks can progress automatically within approval. Worktree changes require operator review before a subsequent package; no source-editing unattended chain is claimed. Active/uncertain outcomes block duplicates and ownership release.

At the account reserve (default 20%) the account collector and foreground dispatcher persist a stop and preserve the current semantic input. A model or effort change cannot bypass shared allowance. Separate windows retain their identity; stale/unknown signals are never zero or recovered capacity. Use the established inspect → fresh review → resume procedure to archive the stop after recovery. If saving fails, ordinary work remains stopped and the previous valid generation stays available.

`setup.py status --project PROJECT` reports prerequisites, bindings, managed customization, native service receipt, collection freshness and hook receipt. `setup.py repair --project PROJECT --reserve 20` idempotently upgrades unchanged managed source and registers/reuses account services/hooks. Customized hooks/runtime and unresolved service transactions require reconciliation. A missing binding is never replaced automatically: inspect queues/stores first, then supply explicit task/project IDs. Native login and `/hooks` trust are device-local. Matching existing services are reused. Verify actual scheduler runs after setup.

Private exchange requires GitHub CLI, device-local login and a private repository whose identity equals the bound project. Source commits must already exist on that repository. Commands:

```sh
python skills/task-checkpoint/scripts/transfer.py --root PROJECT publish --repository OWNER/PRIVATE-REPO
python skills/task-checkpoint/scripts/transfer.py --root PROJECT receive --repository OWNER/PRIVATE-REPO --tag CHECKPOINT-TAG --asset bundle-SHA256.zip --revision SOURCE-COMMIT
```

Enable automatic outbound exchange only by adding `private_transfer:{"repository":"OWNER/PRIVATE-REPO"}` to an existing account project registration after reviewing the transport. The existing collector publishes latest verified state; repeated identical successful generations are suppressed. A failed/offline upload remains pending; retry observes the same immutable tag/asset and validates remote readback rather than overwriting. Competing owners continue to use the existing remote ownership ledger. Transfers never grant leases or authorization. An uncertain worker remains uncertain in task data. Receive never auto-selects the newest checkpoint: explicitly name identity/revision/content-addressed asset to reject stale or conflicting data. The archive includes previous valid generation, artifacts and hashes; excludes credentials, config, receipts, queues and raw logs.

Incoming bundles live at `.checkpoint/incoming/CHECKPOINT-ID/`. They are quarantined. Read `received.json`, `state.json`, `HANDOFF.md`, and manifests. Compare source revision and artifact hashes, reconcile dirty files and jobs, and prepare a fresh current authorization/resource review. Never restore over a working tree, delete an owner, or run a saved command merely because it arrived in a bundle. Keep both states if the target has later local work. The operator guide remains authoritative for reviewed resume. Native Mac↔Windows handoffs are pending until executed on two authenticated devices.

Public exports use `release.py` and the exact `public-export.json` file map. No private history/evidence/runtime state is included. Run export twice and compare SHA256, inspect all exported paths/content, then run the exported tests. For initial publication initialize a fresh Git repository from only that verified export, verify target account/name/visibility, commit, push normally, and compare the remote commit. For later releases fetch the existing public mirror, replace only its manifest-managed files, preserve unexpected user edits for review, run tests and push normally. The private repository stays private. Always retain applicable license notices. Public content has configurable paths, identities, thresholds and assignments.

For reviewed promotion, run `transfer.py --root PROJECT inspect-incoming --id CHECKPOINT-ID`, read the quarantine, and write a current review containing checkpoint_id, current_fingerprint, observed_at, authorization (confirmed/source/scope) and destination_reconciliation evidence. After the source owner releases, `transfer.py --root PROJECT adopt --id CHECKPOINT-ID --review REVIEW.json` promotes data atomically, preserves the prior local generation and any transferred low-resource stop, and never copies execution receipts. Then run checkpoint inspect and the separate fresh reviewed resume procedure. Retain both versions of dirty artifacts; adoption never restores worktree files.

Qualification now requires explicit `model` and `effort` fields matching the worker assignment. A config edit cannot reuse Medium evidence for an untested Low effort or another model. Upgrade existing records only from their actual observed qualification; missing/mismatched identity fails closed. The two existing production public JSON Medium records were migrated from retained live evidence; no coding, private-data or Low-effort qualification was invented.

Automatic inbound exchange is data-only: set `private_receive:{"repository":"OWNER/PRIVATE-REPO"}` on the existing account project, or use `setup.py repair --project PROJECT --private-repository OWNER/PRIVATE-REPO` to configure both private directions explicitly. The same collector locates the newest complete task-specific asset, verifies project/task/source revision/manifest and quarantines it. Unknown/future timestamps, source drift, interrupted assets and conflicts remain pending for source sync/review; no older bundle is silently substituted. It never adopts, acquires ownership or runs a worker. Explicit receive of a named older generation remains available for reviewed recovery. No credentials or permissions move between devices.

New outbound generations under remote ownership require the current source lease. A device that released ownership or sees a foreign owner may still preserve locally and receive into quarantine; it cannot publish a new stale generation as the latest handoff. Already verified identical uploads remain deduplicated after release. Save and let upload/readback complete before releasing the sender lease.
